CASE FILE // HTB-01

HTB — CAP Investigation

01 — Objective

Analyze and obtain authorized access on the target machine in a controlled lab environment by assessing web parameters and system privilege configurations.

02 — Reconnaissance & Enumeration

Performed service scans using Nmap. Discovered HTTP server on port 80 and open FTP/SSH services. Enumerated web routing and identified PCAP download endpoints containing unencrypted traffic analysis capabilities.

03 — Attack Path & Analysis

1. Parameter manipulation (IDOR) on network capture endpoints allowed downloading capture logs of other sessions.
2. Inspected captured PCAP traffic in Wireshark to locate cleartext authentication credentials.
3. Authenticated via SSH using credentials.
4. Analyzed Linux capabilities (`getcap -r / 2>/dev/null`) to locate `setuid` binary permissions allowing privilege escalation.

04 — Technical Evidence
$ getcap -r / 2>/dev/null
/usr/bin/python3.8 = cap_setuid+ep
05 — Defensive Perspective & Remediation

• Implement proper access control checks to verify that requesting users own session PCAP logs (prevent IDOR).
• Enforce strict privilege separation and avoid granting unnecessary Linux capabilities like `cap_setuid` to scripting interpreters.
CASE FILE // FRN-01

Sherlock — Brutus Log Analysis

01 — Objective

Analyze compromised Linux system logs to reconstruct an attacker's authentication timeline and identify brute-force login attempts.

02 — Investigation Methodology

Inspected `/var/log/auth.log` and binary session records (`wtmp`). Filtered failed vs successful SSH login events to establish precise timestamps and source IP addresses.

03 — Key Finding

Identified high-frequency failed SSH authentication events originating from a single host, followed immediately by a successful authentication indicating a successful credential brute-force attack.

04 — Defensive Mitigation

Enforce SSH public-key authentication, disable password authentication, and deploy Fail2ban or automated rate-limiting controls.
CASE FILE // WEB-02

Hwat'sHell Web Shell Analysis

01 — Objective

Investigate web application command handling to understand webshell persistence and execution flow inside a sandboxed Linux environment.

02 — Technical Methodology

Enumerated HTTP POST parameter handling. Identified unvalidated input passed directly to execution functions. Executed controlled reverse shell connections back to local listener.

03 — Defensive Recommendation

Avoid executing system commands directly from web parameters. Enforce strict input validation whitelist and run web servers under unprivileged low-impact accounts.
CASE FILE // WEB-03

Logslinger — LFI Investigation

01 — Objective

Investigate Local File Inclusion (LFI) in a Dockerized environment and map the container boundaries.

02 — Attack Path

INPUT PARAMETER ➔ FILE INCLUSION (`../../../../etc/passwd`) ➔ CONTAINER FILESYSTEM ➔ INTERACTIVE SHELL

03 — Defensive Perspective

Use static file identifier maps or strict basename sanitization rather than raw path parameters in file inclusion functions.
